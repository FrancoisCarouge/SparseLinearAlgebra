The code, data, and stack sizes in bytes of one operation on single precision floating point sparse matrices, per configuration, operation, and optimization level, for version 0.2.0. A configuration is a square matrix of a dense, a tridiagonal, or a diagonal pattern, and of an order of 4, 8, or 16; the dot product operates on its first row and first column vectors. Each operation is linked alone, without any library, for a bare-metal Arm Cortex-M4 target with its single-precision floating-point unit, with GNU 14.2.1: -mcpu=cortex-m4 -mthumb -mfloat-abi=hard -mfpu=fpv4-sp-d16. The flash memory holds the .text, .rodata, and .data sections, the random-access memory the .data and .bss sections. The operands are the caller's; a matrix result is statically allocated, a scalar result returned. The stack is the worst case of the operation compiled as one function: a build that does not inline the library calls may use more or less. The configurations are in benchmark/footprint.

The sizes follow the count of stored elements and of elementary operations of each pattern, not the shape.
